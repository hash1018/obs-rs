The release that reaches macOS, and Linux without NVIDIA. obs-rs now runs
on Apple silicon Macs, composites on any Linux GPU with a Vulkan driver, and
shows the Canvas as a webcam to a meeting on Windows 11 and Linux.

Projects and settings from v0.2.0 open as they are. Nothing needs to be
exported or redone.

## Downloading

| | |
|---|---|
| `obs-rs-v0.3.0-x86_64-windows.zip` | Windows 10 or newer, 64-bit |
| `obs-rs-v0.3.0-x86_64-linux.tar.gz` | x86-64, a GPU with a Vulkan driver or NVIDIA's |
| `obs-rs-v0.3.0-arm64-macos.zip` | Apple silicon, macOS 13 or newer — **new** |

Unpack and run what is inside, as before. There is no installer.

**Windows** needs nothing else. The executable is still not code-signed, so
SmartScreen warns on the first launch: *More info → Run anyway*.

**Linux** no longer needs NVIDIA: a GPU with Mesa's Vulkan driver, AMD or
Intel, is enough, and an NVIDIA driver is still used where it is there.
PipeWire and a glibc no older than the current Ubuntu LTS are needed, as
before.

**macOS** comes as `obs-rs.app`. It is signed ad hoc rather than by a
registered developer, so the first time macOS says it cannot check it: open
**System Settings → Privacy & Security** and choose *Open Anyway* beside
obs-rs, once. macOS then asks for each permission as it is first needed —
screen recording, the camera, the microphone, and Input Monitoring for a
hotkey that works while another application has focus. Capturing what
another application plays needs macOS 14.2.

## What is new

**macOS.** Everything the other two platforms do, on a Metal backend:
Scenes and every source kind, display, window and camera capture, the
system's and one application's sound, recording through VideoToolbox,
streaming, the replay buffer, filters, transitions and web pages — which
reach the compositor as GPU textures, as on Windows. The menu bar is the
system's own, shortcuts answer Command, and hotkeys work from inside other
applications once Input Monitoring is allowed. The one thing it lacks is the
virtual camera.

**Linux without NVIDIA.** Where there is no NVIDIA driver, obs-rs composites
on Vulkan — Mesa's driver on AMD or Intel — and a recording smaller than the
Canvas is scaled there too. With NVIDIA's driver it composites on CUDA, as
before. The archive carries neither: both belong to the system.

**Virtual camera.** *Start Virtual Camera* shows the Canvas as a webcam that
Teams, Zoom, a browser or any other program can pick, on Windows 11 and
Linux, and a hotkey can switch it.

- On **Windows** the camera has to be registered for the whole computer once.
  The first start finds it missing and offers *Install Virtual Camera*, which
  asks for administrator permission and copies it to
  `Program Files\media-pp\vcam`.
- On **Linux** it is the v4l2loopback kernel module. Install the
  distribution's package — `v4l2loopback-dkms` on Debian and Ubuntu — and the
  first start offers to load it, through the desktop's administrator prompt.

**Recordings that survive a crash.** An MP4 recording can be written
fragmented: a recording cut off by a crash or a power cut still plays up to
where it stopped, as a Matroska one already did.

**Replay clips that play as they download.** A saved replay is written with
its index at the front, so a clip shared to a messenger or opened from a
link starts playing before it has all arrived.

## Fixed since v0.2.0

- A looping media file played backwards turned round from the start of a
  second lap rather than from where it was, and one stored as playing
  backwards opened as ended with nothing shown.
- A looping file going round backwards could sit on its last picture for
  good where the seek back to its end failed. It now ends, as one that does
  not loop does.
- A network stream whose server was refusing it was asked again every frame
  of a transition — 32 times in one 300 ms fade — rather than at its
  reconnect interval.
- A media file in which a stream appears only after it has opened no longer
  ends there.
- A first start in a fresh user profile began its log with an error about the
  log folder, before the folder had been made.
- The archives carry the documents the README links to, so it reads the same
  unpacked as on GitHub.

## Known limits

- **No virtual camera on macOS.**
- **A web page on Linux is copied through system memory.** On Windows and
  macOS it reaches the compositor as a GPU texture; on Linux Chromium hands
  over its pixels, which costs more CPU for a large or busy page.
- **No studio mode.** Switching Scenes changes what is on air at once.
- **Streaming is RTMP only.** No SRT or WHIP.
- **Neither the Windows build nor the macOS app is signed by a registered
  developer**, and the macOS app is not notarized.
- **The macOS build is Apple silicon only.** There is no Intel Mac build.
