The release where obs-rs stops being only a recorder. It streams to RTMP
services, filters pictures and sound, fades between Scenes, shows a web page
as a source, and keeps a replay buffer. Most of what the v0.1.0 notes listed
as missing is here now.

Projects and settings from v0.1.0 open as they are. Nothing needs to be
exported or redone.

## Downloading

| | |
|---|---|
| `obs-rs-v0.2.0-x86_64-windows.zip` | Windows 10 or newer, 64-bit |
| `obs-rs-v0.2.0-x86_64-linux.tar.gz` | x86-64, **NVIDIA GPU required** |

Unpack and run what is inside, as before. There is no installer. FFmpeg and
now Chromium travel with the archive, which is why it is far larger than
v0.1.0's — about 180 MB on Linux, where v0.1.0's was 28.

**Windows** needs nothing else. The executable is still not code-signed, so
SmartScreen warns on the first launch: *More info → Run anyway*.

**Linux** needs an NVIDIA driver, PipeWire, and a glibc no older than the
current Ubuntu LTS, as before. The browser engine adds a few libraries that
every desktop installation already has — NSS, ALSA, CUPS, GBM, ATK — and a
minimal or server installation may not.

Run `install-desktop-entry.sh` once on Linux. It was only cosmetic before;
now global hotkeys depend on it. The desktop's shortcuts portal answers only
an application it can name, and it names one by its desktop entry. Without
the entry, hotkeys work only while the obs-rs window has focus, and the log
says so.

## What is new

**Streaming** to any RTMP service — Twitch, YouTube, an nginx of your own.
The stream key is masked in Settings and never written to the log. A
broadcast has its own encoder, bit rate, keyframe interval and height, so you
can stream at 720p while recording at 1080p. A broadcast that drops opens
again by itself. Recording and streaming are independent: run either, both,
or start one partway through the other.

**Filters.** On a picture: chroma key, luma key and colour correction. On
sound: noise suppression, a gate, a compressor and a limiter, on a mixer
channel or on a source's own audio. A source's filters live in the new
**Filters** dock and apply while it runs — dragging a slider does not reopen
a camera.

**Transitions.** Switching Scenes can fade, or fade through black, over a
length you set. The default is still an immediate cut. Each placement can
also fade in when it is shown and out when it is hidden, and has an opacity
of its own.

**A web page as a source** — an overlay, an alert box, a chat window —
rendered by Chromium with real transparency. Its sound gets a mixer channel
and is recorded. With **Interact** switched on, your clicks and typing go to
the page, so a page that needs logging into or scrolling can be handled from
the Preview. A page nothing is showing stops drawing, or can be shut down
entirely until it is shown again.

**A Scene inside a Scene.** Keep an overlay in one Scene and place it in
every Scene that needs it; edit it once and it changes everywhere. It
arrives as one picture, so it moves, crops and filters as one thing.

**Replay buffer.** Keeps the last stretch of the canvas in memory and writes
it to a file when you press its key — the clip you only knew you wanted after
it happened. It runs with or without a recording.

**Text source.** A caption or name plate drawn by obs-rs, or a clock that
keeps time.

**One application's sound** on a channel of its own: the game goes to the
recording and the voice chat does not, or the other way round. It is
remembered by the executable, so it finds the application again after a
restart. Windows and Linux both.

**Global hotkeys**, on both platforms: recording, streaming, the replay
buffer, screenshots, the projector, a key per Scene and per source in a
Scene, and push-to-talk and push-to-mute for every mixer channel. They work
while another application has focus — a recorder has to be reachable from
inside the game it is recording. On Linux the desktop asks once whether to
allow them. The two keys obs-rs comes with, `Ctrl+R` to record and `Ctrl+P`
to pause, still work only in its own window, as they did in v0.1.0: every
browser and editor has its own use for them. A key you choose in Settings
works everywhere.

**Undo and redo** for edits: moving, resizing, cropping, renaming, deleting.
A deleted source comes back with its filters, strokes and placement. What is
operated rather than edited — a fader, a mute, play and pause — is left
alone.

**Projector.** The canvas alone on another screen, from `View → Projector`.
It has no outlines, toolbar or docks, and costs no extra encoding.

**Screenshots** of the canvas, or of one source's own picture, as PNG beside
your recordings.

**More video plays.** A codec the GPU cannot decode — ProRes, Motion JPEG,
DNxHD — decodes in software instead of refusing to open. AV1 and 10-bit
video decode on the GPU. HDR and BT.2020 video come out in the right colours
instead of washed out. A ProRes 4444 file keeps its transparency.

**Faster, slower and backwards.** A media file plays at anything from 25% to
400% of its speed, its sound at its own pitch, and can turn round and play
backwards from the picture it is on. Backwards it has no sound — its mixer
channel stays, dimmed, and says why — and it stops at the start: looping
backwards is not there yet.

**Knowing what is wrong.** A source that is not showing says why — the
missing file, the refused password, the camera another program holds — on
its badge in the Sources dock and in the Properties dock. The status bar's
`LAG` reading warns when a recording or broadcast is falling behind, before
it fails. The **Stats** dock breaks that down per output, as OBS's does.
obs-rs keeps a log of its own, a file a day for a week: in
`%LOCALAPPDATA%\obs-rs\logs` on Windows and `~/.local/share/obs-rs/logs` on
Linux.

## Fixed since v0.1.0

- Raising the Desktop Audio fader could fill the speakers with a runaway
  echo, in a project that had monitoring switched on for Desktop Audio.
  Desktop Audio is now never played back, whatever the project says.
- Recordings were named in UTC rather than your own time: one started at
  8:30 in the evening in Seoul was named `…-113000`. New files take the
  local time; existing files are not renamed.
- A camera placed twice in one Scene kept stopping and reopening every
  couple of seconds. A camera is now opened once and shared by every
  placement, and a window shown twice is captured once.
- Recordings did not say which colour space they were in, so players
  guessed wrong and reds came out visibly off. They now state BT.709.

## Known limits

- **Linux is NVIDIA-only**, as before. The Linux backend composites on CUDA
  and has no fallback.
- **A web page on Linux is copied through system memory.** On Windows it
  reaches the compositor as a GPU texture. On Linux Chromium hands over its
  pixels, which costs more CPU for a large or busy page.
- **No studio mode.** Switching Scenes changes what is on air at once; there
  is no separate preview to prepare the next Scene in.
- **Streaming is RTMP only.** No SRT or WHIP.
- **The Windows build is unsigned.**
