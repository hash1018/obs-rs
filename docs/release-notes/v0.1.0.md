An OBS-style scene compositor and screen recorder, written in Rust on top of
[`media-pp`](https://github.com/hash1018/media-pp). It captures your desktop,
composites it on the GPU, and records it — with an annotation layer you can
draw on while it runs.

This is the first release. It is a working recorder rather than a finished
broadcaster, and the limits at the bottom are worth reading before the
features.

## Downloading

| | |
|---|---|
| `obs-rs-v0.1.0-x86_64-windows.zip` | Windows 10 or newer, 64-bit |
| `obs-rs-v0.1.0-x86_64-linux.tar.gz` | x86-64, **NVIDIA GPU required** |

Unpack and run what is inside. There is no installer, and nothing is written
outside the folder except your own settings and project under your user
directory. FFmpeg travels with the archive and does not have to be installed.

**Windows** needs nothing else — the Visual C++ runtime is in the archive.
The executable is not code-signed, so SmartScreen will offer to protect you
from it the first time: *More info → Run anyway*.

**Linux** needs an NVIDIA driver, PipeWire, and a glibc no older than the
current Ubuntu LTS. The driver is not an accelerator here but the only
compositing path there is, so an AMD or Intel machine will not start it.
`libcuda.so.1` and `libpipewire-0.3.so.0` are deliberately not bundled: one
belongs to your driver, and the other is a client for a system service that a
bundled copy could only disagree with.

The Linux archive also carries `install-desktop-entry.sh`, which gives the
application a name and an icon in the launcher. It writes under
`~/.local/share` and needs no root. On Wayland it is the only way the window
gets an icon: the protocol has no call for a client to set its own, so the
compositor matches an installed entry instead.

## What it does

**Scenes and sources.** A Scene is a list of sources on a 1920×1080 canvas —
move, resize, crop, reorder, hide, lock and rename them. Duplicating a Scene
places the same sources again rather than capturing them twice, so one source
can appear in several Scenes with its own position in each.

**Eight kinds of source.** Display Capture and Window Capture on both
platforms, with frames going straight into GPU memory and staying there
through compositing and encoding. Video Capture for a webcam. Media File for
a video, decoded on the GPU, pausable and scrubbable. Network Stream for an
RTSP camera. Image, Drawing and Color.

A source whose target is not there is not an error. A closed window, an
unplugged camera, a stream that stopped answering: each waits where it is and
is picked up again when it comes back.

**Recording** to MP4, Matroska or HLS, with hardware encoding where the
machine has it, and one recording splittable into several files by elapsed
time or by size.

**Audio.** Desktop and microphone channels with faders, mute, and meters that
read after the fader. Every media file and stream in the Scene gets a channel
of its own. Monitoring plays a channel to an endpoint you pick in Settings,
kept apart from the one Desktop Audio listens to so that what you are hearing
does not reach the recording twice.

**Drawing** is a real layer rather than an overlay on your screen: pen,
highlighter and eraser, with undo, and what you draw is in the recording.

**A workspace that stays put.** Docks move, resize and close, and where they
were is remembered along with the window and the Preview's zoom. English and
Korean, from `View → Language`.

## Known limits

- **No streaming.** There is no RTMP output, so nothing goes to Twitch or
  YouTube. Recording is the whole of it.
- **Linux is NVIDIA-only.** The Linux backend composites on CUDA and has no
  fallback.
- **No filters or transitions.** Switching Scenes is a cut.
- **The Windows build is unsigned**, so its first launch has a SmartScreen
  warning to click through.
